Implementation Engineer. לבנות את המסך **בדיוק** לפי ה-reference, ממופה לשדות ה-backend האמיתיים. לא לשנות ארכיטקטורה / Decision-Guidance-Engine / פלואו / מפת-ההכרעות.

## העיקרון המרכזי (זה מה שמצמיד עיצוב ל-backend)
המסך בנוי **סביב משפט אחד**, לא סביב שדות. **המשפט הזה = `customerBenefitText`** — השדה היחיד שבאמת נשמר. כל מה שבמסך (Builder, scope, תנאים) הוא UX ש**מרכיב** את המשפט. לכן: אין צורך ב-backend חדש כדי לבנות את המסך — הכל מתנקז ל-`createOffer` הקיים.

## מיפוי ל-backend (מה נשמר — createOffer)
`createOffer` שולח **רק**: `title`, `customerBenefitText`, `description?`, `imageUrl?`, `validUntil`.
- **`customerBenefitText`** = המשפט המורכב (למשל "20% הנחה על כל העסק"). 🟢 אמיתי.
- **`title`** = אותו משפט, ניתן לעריכה (ברירת-מחדל = customerBenefitText). 🟢 אמיתי.
- **`description`** = התיאור הקצר האופציונלי. 🟢 אמיתי.
- **`validUntil`** = התוקף (ברירת-מחדל שבועיים). 🟢 אמיתי.
- **סוג ההטבה / אחוז / scope / תנאים כשדות מובנים ב-DB** = 🟡 `[needs-confirm]`. **בשלב זה: לא ליצור עמודות DB חדשות.** מרכיבים אותם לתוך `customerBenefitText`/`description`. אם תרצו אחסון מובנה בעתיד — שלב backend נפרד לאישור.

## מבנה המסך (בדיוק לפי ה-reference)
1. **תצוגה מקדימה חיה** (בראש) — כרטיס הקופון כפי שהלקוח יראה, עם המשפט. **מתעדכן על כל שינוי** בזמן אמת (state → render). לא preview טכני — זהה לכרטיס הצרכני.
2. **"מה הלקוח מקבל?"** — Builder: 7 צ'יפים אוניברסליים (אחוז הנחה · סכום הנחה · מחיר מיוחד · מוצר במתנה · שירות במתנה · יותר תמורה · אחר). **חשיפה מותנית:** בחירת סוג פותחת **רק** את השדה הרלוונטי שלו.
3. **"על מה זה חל?"** — צ'יפים: כל העסק · מוצר מסוים · שירות מסוים · קטגוריה · בחירה ידנית.
4. **"איך זה ייקרא ללקוח"** — שדה כותרת **מורכב אוטומטית**, ניתן לעריכה, + "הוסף תיאור קצר (לא חובה)".
5. **"תנאים · רק החשוב"** — צ'יפים לבחירה (toggle): פעם אחת ללקוח · מינימום רכישה · לקוחות חדשים · סניף מסוים · תוקף.
6. **CTA:** "צור את הקופון" → `createOffer`.

## חשיפה מותנית לכל סוג (contextual fields)
- אחוז הנחה → שדה מספר `%` → קטע-משפט: "N% הנחה".
- סכום הנחה → שדה מספר `₪` → "N₪ הנחה".
- מחיר מיוחד → שדה מספר `₪` → "במחיר N₪".
- מוצר במתנה → שדה טקסט "מה מקבלים" → "[מוצר] מתנה".
- שירות במתנה → שדה טקסט → "[שירות] מתנה".
- יותר תמורה → תת-בחירה (1+1 / כרטיסייה / חבילה / שדרוג) → שדה פרטים → קטע מתאים.
- אחר → שדה טקסט חופשי → הטקסט עצמו.

## לוגיקת הרכבת המשפט (זהה בכל תחום)
`customerBenefitText = "{קטע-הטבה} על {scope}"`
- `{קטע-הטבה}` מהסוג הנבחר (למעלה).
- `{scope}`: כל העסק → "כל העסק" · מוצר/שירות/קטגוריה → הערך שנבחר · בחירה ידנית → הרשימה.
- **תת-שורה בתצוגה** (לא ב-customerBenefitText בהכרח): תוקף + תנאים ("תקף שבועיים · פעם אחת ללקוח").
- `title` = ברירת-מחדל = `customerBenefitText`, editable.
> הכלל: **כל רכיב במסך חייב לשנות את המשפט.** אם רכיב לא משפיע על המשפט — הוא לא שייך למסך.

## אוניברסליות (מחייב)
בלי לוגיקה או מסלול תלויי-ענף. אותם 7 סוגים + 5 scopes + תנאים עובדים למסעדה, קפה, מספרה, קוסמטיקאית, רופא, עו"ד, מוסך, חנות בגדים, חדר כושר, מאמן, מרפאה — כל עסק. אין `if industry ==`.
