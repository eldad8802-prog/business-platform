## 0. מוסכמות קריאה

**RTL:** הדף עברי. **בכל הדיאגרמות — צד ימין של התרשים = צד ימין של המסך.**
העין מתחילה מימין.

**תוויות באנגלית בתוך התרשימים** — בכוונה. עברית בתוך תיבות ASCII שוברת את
היישור (bidi). ההסבר בעברית תמיד **מתחת** לתרשים.

**סולם גובה** (ביחס לגובה מסך טלפון = 1.0):

| סימון | גובה | תחושה |
|---|---|---|
| `XS` | ~0.15 | רצועה. עוברים דרכה |
| `S` | ~0.35 | נשימה |
| `M` | ~0.7 | סקשן רגיל |
| `L` | ~1.0 | תופס מסך מלא |
| `XL` | ~2.5+ | אזור, לא סקשן |

**משקל עין:** `●●●` מושך ראשון · `●●` משני · `●` רקע.

```

│  │   (his world)      │            │ "no setup"                │ │
│  │                    │            │                           │ │
│  │                    │            │ [ PRIMARY CTA ] ●●●       │ │

└──────────────────────────────────────────────────────────────────┘

MOBILE
┌──────────────────┐
│ H1          ●●●  │   ← text FIRST. visual does not push it down
│ sub          ●●  │
│ [ CTA ]     ●●●  │
│ ─────────────    │
│ VISUAL       ●●  │   ← partially below fold = pulls the scroll
│ trust-seed    ●  │

```

| | |
|---|---|
| **גובה / רוחב** | `L` · Container |
| **ימין (דסקטופ)** | **הטקסט.** הבטחה ← משנה ← CTA ← זרע אמון |
| **שמאל** | הוויזואל |
| **CTA** | אחד, מתחת למשנה. לא מוגדל־יתר |
| **מושך עין** | H1, ואחריו CTA |
| **משני** | זרע האמון — **נקרא, לא בולט** |

**הכרעת מובייל:** **הטקסט קודם לוויזואל.** ויזואל שדוחף את ההבטחה מתחת לקיפול הוא
הכשל הנפוץ ביותר בדפי נחיתה. הוויזואל **נחתך** בתחתית המסך — וזה בדיוק מה שמושך
את הגלילה הראשונה.

**תפקיד הוויזואל:** **שיוך, לא הרשמה.** הוא עונה על "זה בשבילי?" בחצי שנייה.
❌ לא קולאז' מסכים · ❌ לא דמות · ❌ לא איור מופשט של "ניהול".

|---|---|
| **גובה / רוחב** | `M+` · **Container צר** (עמודה אחת, שורות קצרות) |
| **ימין / שמאל** | **אין פיצול — ובכוונה.** פיצול היה הופך רגש לטיעון |
| **טקסט** | **כל הסקשן.** זה הסקשן היחיד שנקרא מילה במילה |
| **ויזואל** | **אין מוצר.** לכל היותר רמז חזותי לפיצול/קטיעה |
| **CTA** | **אין. מכירה כאן הורגת את הזיהוי** |
| **מושך עין** | הכותרת, ואז שורת שחרור־האשמה |

**החלטה קריטית:** **רקע מנוגד** — זו **שבירת הקצב הראשונה בדף**, והיא מסמנת
פיזית: *עכשיו לא מוכרים לך, עכשיו מדברים עליך.*

⚠️ **זהו הסקשן היחיד ש-Wireframe לא יכול להציל.** המבנה שלו טריוויאלי; **כל
עוצמתו בקופי.** אם הניסוח לא מדויק — הדף מת כאן, ושום פריסה לא תעזור.

**כותרת התוצאה חייבת לעמוד לבדה.** מי שקורא רק כותרות — חייב להבין את כל S5.

## 5.1 שני המעברים שדורשים טיפול

נשען על כך שהקיפול יסתיים במשהו שמייצר **חוסר**. ⚠️ הכרעה שנופלת על הקופי.
**חיזוק מבני אפשרי:** חיתוך מכוון של S2 בתחתית המסך — טקסט שנקטע באמצע מייצר
גלילה כמעט אוטומטית.

**S6→S7 (חלשה):** לגיטימציה סוגרת נושא במקום לפתוח. שלוש אפשרויות:
1. **למזג את S6 לתוך S5** כרצועת סיום → S7 נצמד ישירות להוכחה.

3. להשאיר, ולסמוך על S7 להיות **קצר וקל מאוד** לכניסה.

> **המלצה: אפשרות 2** — היתר לפני בקשה הוא רצף חזק יותר מהיתר באמצע. נדרשת בדיקה

# 6. ביקורת עצמית

## 6.1 מה עדיין חלש

1. **S2 אינו ניתן להצלה מבנית.** המבנה טריוויאלי, וכל עוצמתו בקופי. זהו **הסקשן
   החשוב ביותר בדף שה-Wireframe לא אומר עליו כלום.**
2. **S1 נושא עומס בלתי אפשרי:** תוצאה + שייכות + היעדר הקמה + זרע אמון + CTA —
   **חמישה תפקידים בשמונה שניות.** מבנית זה צפוף מדי, ולא מצאתי דרך להוריד אף
   אחד מהם.
3. **אין הוכחה חברתית בשום מקום.** אין המלצות, אין לוגואים, אין מספרים. **חור
   שמבנה אינו יכול לסתום** — רק לקוחות אמיתיים.
4. **S3 עלול להיראות גנרי.** תרשים "מקורות ← מערכת" הוא הקלישאה של כל דף B2B.
5. **S7 חלש משני הכיוונים** — מעבר חלש נכנס (§5.1) ופריסה דומה ל-S8 (§3.2).
   **המועמד הראשון לירידה.**

## 6.2 היכן נאבד משתמשים

| 2 | **S3→S4 — פחד הפרטיות** | **הנטישה השקטה שלעולם לא נראה** | **כן.** S4 חייב להיצמד |

## 6.3 היכן הדף ארוך מדי

- **סה"כ 10 סקשנים** — לפרסונה שקוראת בין שתי עבודות, זה **סקשן־שניים יותר מדי**.
  המועמדים: S7, S5d.
- **S9** — יגדל מעצמו עם הזמן. צריך תקרה קשיחה (4–5 שאלות).

## 6.4 היכן הדף קצר מדי

- **S4 (S)** — קצר **בכוונה**, אבל ייתכן שקצר **מדי** מכדי להרגיע פחד אמיתי מפני
  קריאת וואטסאפ. ⚠️ **הפער הכי לא־ידוע בדף. חייב בדיקה מול משתמשים.**
- **S6** — רצועה בלבד; ייתכן שלא תספיק למי שהפחד הבירוקרטי שלו דומיננטי.

  **חוסר אמיתי** — ואין לו מקום מבני.

## 6.5 מה אי אפשר להכריע לפני עיצוב אמיתי

1. **האם S2 עובד ללא ויזואל כלשהו?** אולי בלוק טקסט טהור ייקרא כ"מאמר" וידולג.
2. **האם ויזואל השיוך ב-S1 אפשרי בלי אדם?** צילום אדם אמיתי בונה שייכות מיידית
   — וצילום סטוק הורג אמון בשנייה. **שאלת מיתוג, לא שאלת פריסה.**
3. **האם ה-zig-zag ב-S5 ייקרא כקצב או כתבנית?** תלוי לגמרי במרווחים ובגדלים.
4. **האם ההיררכיה הטיפוגרפית תישא "מסקנה לפני נתון"?** כל הדף מניח שכותרות
   עומדות לבדן. **לא ניתן לאימות בלי טיפוגרפיה אמיתית.**
5. **כמה רקעים מנוגדים הדף סובל?** תוכננו שלושה (S2, S8 + S6 שקט). יותר — הדף
   מתפרק; פחות — מונוטוני במובייל (§4.2).
6. **האם S5 שורד במובייל בשלוש שורות?** ייתכן שנצטרך לרדת לשתיים — וזו הכרעה
   שדורשת לראות אותן על מסך.
